# Evidence-bound review and correction

Routine source/opinion models read one complete inline review_card and send its
semantic answer JSON on stdin to the returned checked review HANDLE command.
Code saves input and returns the next complete card; no file/path assembly. Code copies exact acquired quotes and metadata and compiles the
existing receipt; model-authored citations, hashes and fragment readers are not
normal requirements. See SHORT_REVIEW_SPEC.md and SMALL_REVIEW_PACKETS.md.

The sole returned ordinary submission command uses review_step.py, which logs
each attempt and atomically advances the pointer. Formatting whitespace in contact
values may be equivalent; exact original/quote/hash support is never normalized.
Use supplied handoff_text at authorized stops; no directory/count reconstruction.
Opinion screening/field rules are in OPINION_DISCOVERY.md; complete bare PCAs do
not require underlying-case research, and source differences alone do not require
resolving conflicting authorities or adding public bookkeeping.

## Normal review integrity

Hash/status comparison and completed-review reuse run before a model task. Read
only the returned court/law/personnel evidence. Preserve date meanings, practical
civil/commercial scope, separate successors and documented conflicts. Unverified
browser behavior, technical causes and legal effect must not be invented.

Unknown original/nontext changes, missing/oversized acquired evidence and model
uncertainty remain pending source-bound exceptions. Ordinary tasks continue;
review_exceptions is not completion and cannot advance the finalized baseline.
HTTP 200/loading stubs are not successful content review. Exact error records and
originals remain preserved. No public research-incomplete or reconciliation prose.

## Auditing completed work

A requested audit of a completed update starts with saved substantive reviews,
corrections and validation results. Reopen an item for a concrete factual or
legal defect, missing substantive content, material omission, conflict, failed
validation, or a demonstrated failure mechanism that plausibly affects it.
Compaction, generic wording and shared hosts/templates are not reopening reasons.

Bound recurring-defect checks with representative evidence and count checks
already completed. A supported sample permits bounded reuse; it does not certify
individual review of every item. An audit list is not an obligation to re-review
all its entries. Preserve acceptable findings, prose, contacts and provenance;
correct only defects. Do not research website assets or historical materials
without a specific material publication need. Honor the user's audit-expansion
checkpoint. Keep individually verified work, supported reuse, corrections and
unresolved material issues distinct, and retain ordinary publication validation.

## Failed answers and full-receipt maintenance

The checked answer helper saves original answer bytes, packet binding, stdout,
stderr and exit codes. Code also saves rejected answers/errors and, after two
rejections, checkpoints unresolved work and returns another ordinary task. Do not
repeat the previous packet automatically. There is no model-authored repair note
for short answers; a genuinely corrected answer can be accepted later. A committed
submission followed by failed advancement is retried with next or the exact answer.

Full submit/revise remains for explicit maintenance and downstream approval. Its
legacy repair-note gate still requires packet_sha256, failed_attempts,
change_in_approach and evidence_paths after two rejected full receipts. That is
not a second routine source-review protocol. V7 raw-group and exact-quote helpers
remain available to an explicit technical reviewer. Unknown group significance
cannot supply completed no-change proof; bindings alone do not certify interpretation.

## Production corrections

When a source already has an accepted workflow decision, revise that exact
packet through `workflow revise` with its current decision hash as predecessor.
This updates the source review and coordinator decision together. A direct
`source-gate review` changes only the domain receipt and leaves the coordinator
inconsistent. If interruption occurs after the domain commit, resume the exact
revision with the same receipt, predecessor and reason before advancing the
queue; the revision API supports that recovery. Verify agreement before any
downstream preparation. Keep database mutations sequential with next/reply.

Use append-only commands through the pinned launcher:

```sh
flwu source-gate withdraw --database DB --registry RUN/expanded-registry.json --receipt WITHDRAWAL.json
flwu source-gate correct-content --database DB --registry RUN/expanded-registry.json --receipt CONTENT_CORRECTION.json
```

A withdrawal receipt has exactly `receipt_sha256`, `reviewer`, `reason`, bound to
an accepted review. Its original remains recorded but cannot supply raw/content/
component or supplemental reuse proof, nor be replayed as accepted. Preserve a
specific reason; withdrawals are immutable. Re-review through the returned
`source_review_correction` and checked `revise` with the exact predecessor, or
review a newer observation through its new source task. Do not edit old receipts.

A content correction has exactly `observation_capture_id` and `reviewer`. It
currently recognizes the tested Senate cookie/loading stub. It appends corrected
availability while preserving the actual original URL/hash/retrieval timestamp
and HTTP status. It does not download, backdate or invent replacement content.
Future acquisition excludes the corrected response from successful comparison
baselines and uses the last valid content observation when available.
Other source limitations require their supported evidence path, not this shortcut.

An embedded browser PDF has no inferred HTTP status. For the saved
`browser-embedded-pdf-data-uri-v1` acquisition, publication checks the immutable
browser snapshot against its recorded hash, URL and retrieval time, decodes its
PDF data URI, and requires the decoded bytes to match the acquired original.
Original and extracted-text hashes and quoted support still must pass. Preserve
the exact browser snapshot as an artifact; a browser label alone is insufficient.
Do not invent a transport status or retrieve an already saved document again to
make its citation resemble an HTTP acquisition.

Retain valid findings and source conflicts. Do not turn uncertain technical state
into a completed no-change receipt. Keep unresolved limitations internal; do not
add research-incomplete notices to public headings. Discovery-only observations
and after-cutoff events do not establish a publishable legal change. Preserve
historical reports and the last finalized reporting baseline.

An explicitly requested production repair may apply a frozen, independently
reviewed manifest of exact accepted-receipt hashes and separately authored
replacement receipts through the normal validated correction APIs. This is a
bounded data repair, not a normal research loop: it must not discover more tasks,
choose verdicts, broaden the source set or continue the weekly workflow. Preserve
predecessors, per-item results and interruption recovery. This exception does not
authorize an interactive runner to manufacture no-change receipts for its queue.
