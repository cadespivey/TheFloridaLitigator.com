# Deterministic publication from reviewed findings

Approved November 11, 2026. The invoking model reviews meaning; code carries
reviewed data to the website. This supersedes routine model-authored mapping,
directory, roster and acceptance receipts in the standard continuation route.
Legacy receipt APIs remain maintenance/recovery interfaces.

## Implementation boundaries

1. Continue through the checked inline next/reply interface. Derive mappings for
   reviewed opinions with supported dates, structured publication candidates,
   personnel with known scope, and internal provenance/conflict records. Do not
   infer statutory amendments, effective dates, court membership or departures.
2. Code copies citations, versions, IDs and unchanged fields; it projects exact
   personnel identities and explicitly supported scope/removals, reconciles named
   inventories and applies existing domain validators. Ambiguous aliases,
   missing publication metadata and unsupported scope are small semantic tasks,
   not instructions to copy a full receipt or restart research.
3. Automatically prepare the report, update unambiguous directory rows, reconcile
   rosters and build/check the current website. Do not ask the model to reapprove
   unchanged rosters. Keep exact before/after audit records.
4. Retain one compact content approval bound to the exact report/build. Present
   reviewed current entries and changed directory rows, not historical reports.
   Code owns the acceptance manifest. Approval is an actual model/user decision,
   not a generated claim of independent legal or human visual review. Corrections
   append through existing domain revision APIs and invalidate derived artifacts.
5. After approval, code finalizes/exports/integrates. An explicitly executed release
   command handles ordinary Git/PR/CI/merge/deployment under existing publication
   authorization. It never force pushes, discards edits or changes remote settings.
   Interrupted operations resume their recorded branch/PR/commit. Pending/failed
   CI, credentials, concurrent edits and evidence gaps remain precise checkpoints.
6. Completion requires the existing exact-commit and live-current-data verifier.
   Preview completes without production writes. No historical-report audit.

## Validation

Use disposable databases/repositories and frozen/synthetic captures. Test current
and out-of-window opinions, supported rule metadata, missing facts, known versus
ambiguous personnel IDs, explicit removals, unchanged roster reuse, correction
invalidation, interrupted commit/advance, tampered artifacts and rejected approval.
Exercise the actual checked standard command through accepted preview and the
publication executor through mocked GitHub/live boundaries. Verify no inference
is requested for routine transfer and no unresolved source becomes no-change.
Production deployment is not authorized merely by implementing/testing this path.

The current-only review preview never binds a county alias to an absent older
primary row. Unused aliases remain unchanged in the supplement; mismatches for
present identities still fail. Generic preview and production builds retain their
strict complete-archive alias checks. This avoids historical report audits while
keeping production identity validation intact.

Release waits reuse remote-file verification only for the identical immutable
commit and exact integrated bundle hash. New heads/merge commits recheck bytes.
Live archive pointers/data remain freshly checked. Failure diagnostics stay in
private run logs; model-facing checkpoints contain the operation and log path,
not credentials/private identity. Timeout and failure states remain visible after
resume. No force pushes, reset/discard or remote-configuration mutations occur.

Reporting scope remains explicit. A default interval starts after the finalized
baseline; an explicit start may include already approved items in that interval.
Code reuses their approved text and citation bindings instead of asking for a new
analysis. Outside the requested interval, unchanged findings do not become news.
Undated approved findings retain their recorded reporting-period meaning; code
does not turn that period into an invented publication or effective date.
