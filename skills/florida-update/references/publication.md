# Deterministic release from reviewed findings

The checked next/reply route automatically performs ordinary mappings, exact-ID
personnel projections, named roster reconciliation, report/site build and artifact
checks. Do not copy receipts, hashes, quotations, versions or unchanged rosters.

Only missing legal metadata, ambiguous scope/identity, county-specific assignments
and actual evidence failures need semantic answers. The returned compact card is
the complete routine input/output contract. A new name is not a rename; omissions
are not departures. Code never invents removals, dates or amendments.

At publication_acceptance, read current entries and changed directory rows. Use
approve plus an actual reason, correct plus N-reference/changed opinion fields and
reason, or unresolved. Code generates the complete bound manifest; corrections use
append-only domain revisions and cause a rebuild/new approval. Automated artifact
checks are not independent human/browser review and do not prove legal truth.

After approval, preview returns preview_complete without publication. Publish mode
finalizes, exports and integrates the exact bundle. The returned workflow release
--execute --merge --wait command performs ordinary Git/PR/CI/deployment steps under
the invocation's publication authorization. Do not execute a publication command
for a user-limited preview/test. No force push, history rewrite, remote settings,
model/server changes or unrelated staging is authorized.

The executor preserves unrelated edits, requires unrelated staged work to be
resolved, refuses unreleased implementation changes in a data-only release,
checks exact staged/committed bundle bytes and the credential scan, and uses the
required no-reply author/committer. It reuses the recorded branch/commit/PR. Failed
CI cannot merge. Successful PR checks or a build are not a deployed website.

Next/reply can also stay quiet during report/directory/site generation. Wait on
its running numeric session_id; no output does not establish a stall. Do not
resubmit an accepted answer or start another acquisition.

Wait on the single running release process. It owns bounded CI/deployment waits. On timeout
or failure retain the exact run and release checkpoint; rerun that same command
only after the reported condition changes. Never rerun research to repair deploy.
Only publication_complete means exact merged commit, successful Pages deploy and
matching live current report/directory data. Preserve historical reports without
auditing them. Record the returned PR/deployment URLs and phase in RESUME.md.

For unresolved semantic publication cards, use the returned checked retry command
only with a genuinely corrected answer. It restores the complete inline card and
preserves the original error/evidence. Identical rejected answers remain rejected.
Legacy submit/revise and manual release-plan/verify-deployment are maintenance
interfaces, not a second standard workflow.
